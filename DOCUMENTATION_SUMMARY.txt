🔴 CRITICAL LESSONS DOCUMENTED
═══════════════════════════════════════════════════════════════════════════════

Piège #1: Jackson LocalDateTime Serialization (❌ 100% failure if missed)
├─ Symptom: "LocalDateTime not supported by default"
├─ Cause: Missing jackson-datatype-jsr310 dependency
├─ Fix: Add dependency + ObjectMapper.registerModule(new JavaTimeModule())
└─ Documented in: All 6 files, highlighted as CRITICAL

Piège #2: Spring Cloud Stream Dependency Unavailable
├─ Symptom: "Could not resolve dependency"
├─ Cause: Spring Cloud dropped Redis support
├─ Fix: Use RedisTemplate direct (already provided)
└─ Documented in: TECHNICAL_CHOICES section 2

Piège #3: Date Arithmetic Across Month Boundaries
├─ Symptom: "Expected 5 days but got -26"
├─ Cause: Using getDayOfMonth() instead of ChronoUnit
├─ Fix: ChronoUnit.DAYS.between(start, end)
└─ Documented in: TECHNICAL_CHOICES section 11

Piège #4: RedisTemplate.rightPush() Returns Long
├─ Symptom: "Type error: Long cannot be cast to boolean"
├─ Cause: Mistaking return type
├─ Fix: Check result != null && result > 0
└─ Documented in: QUICK_START_REDIS_EVENTS section pièges

Piège #5: Mock Verification Matcher Mismatch
├─ Symptom: "UnnecessaryStubbingException"
├─ Cause: Mixed any() and eq() matchers
├─ Fix: Use explicit matchers consistently
└─ Documented in: TECHNICAL_CHOICES section 8

Piège #6: Docker Hostname localhost vs Service Name
├─ Symptom: "Unable to connect to localhost:6379 in Docker"
├─ Cause: localhost = container itself, not Redis service
├─ Fix: Use service hostname "redis" in Docker Compose
└─ Documented in: TESTING_EVENT_PUBLISHING troubleshooting

🎯 ARCHITECTURAL DECISIONS
═══════════════════════════════════════════════════════════════════════════════

Decision #1: RedisTemplate Direct (vs Spring Cloud Stream)
├─ Why: Available, simple, testable, production-proven
├─ Alternative: Spring Cloud Stream (NOT AVAILABLE!)
├─ Trade-off: Simple queue logic, no complex binding
└─ Documented in: TECHNICAL_CHOICES section 2

Decision #2: Redis Lists MVP (vs Streams vs Kafka)
├─ Why: O(1) operations, simple, MVP timeline
├─ Alternative: Streams (for consumer groups), Kafka (for scale)
├─ Trade-off: No consumer groups yet, but upgradeable
├─ Upgrade path: Lists → Streams (same queue name)
└─ Documented in: TECHNICAL_CHOICES section 5

Decision #3: LocalDateTime + JavaTimeModule
├─ Why: Human readable, timezone support, industry standard
├─ Alternative: Instant (UTC only), Epoch (unreadable)
├─ Trade-off: Requires explicit module registration
└─ Documented in: TECHNICAL_CHOICES section 3

Decision #4: Non-Blocking Publisher Pattern
├─ Why: Resilience, graceful degradation
├─ Alternative: Blocking (transaction fail if Redis down)
├─ Trade-off: Event may be lost if Redis unavailable
└─ Documented in: TECHNICAL_CHOICES section 14

Decision #5: Metadata Wrapper Format
├─ Why: Routing, traceability, multi-event support
├─ Format: {eventType, eventId, timestamp, data}
├─ Alternative: Flat domain event (simpler but less flexible)
└─ Documented in: TECHNICAL_CHOICES section 4
